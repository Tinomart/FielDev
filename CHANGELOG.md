# Changelog

FielDev is a fork of FielDes (a field-driven design workbench: a C++ kernel on libfive, a Python library and a Qt application), trimmed for **modelling for game development**.
What FielDes did before the fork is in the git history of this repository (this file used to hold it).

## 1.0.0 (not released)

### The Characters section is its own; a playful look; words a game developer knows
- **New armature is a mode of its own, not the work plane.** *Draw an armature* is gone, and so is the Armature button of the work plane (which is for 2D drawing only: Line, Spline, Point). *Characters ▸ New armature* puts the nodes down **one click after another and writes each into the script as it is put down**: the first click makes the armature (`armature([...], profile=armature_1_cut)`, with its cross-section and its cut face), every click after adds a node (a point with a gizmo, in the list of the call; `profile_edit.py`, op `armature`) in the plane through the node before it that faces the camera, so turning the view puts the next one in depth. **A click on a node goes on from it**; from a node in the middle the armature **branches** (a new armature that begins on the same point, which `skeleton_of` hangs from that joint). A right click or Esc goes back a step -- from the node to none, then out of the mode --, Ctrl+Z takes the last node back, and *Add nodes from here* is in the menu of a node. An armature of one node is a ball with its cross-section (`cut_face` works on it).

### Armatures are path extrudes; radius circles; feature models; UV maps by part
- **A hex colour is sRGB.** `material(..., color="#3a6ea5")` read the hex as linear numbers, so it looked lighter in the viewport and in an engine than the same hex in a paint program (the open decision of the known issues). It is read as sRGB now, as everywhere else a hex colour is typed, and converted to linear when the material is made (`materials._rgb`); a colour given as `(r, g, b)` numbers stays linear, as glTF has them. No colour dialog was added: a hex colour is typed in the script, where it reads plainly. Example 34 checks the converted values.
- **An armature is a path extrude with an automatic cross-section.** `armature(points, radii, profile, ...)` sweeps a profile along the Catmull-Rom spline through its nodes (the round cones are gone from it; `chain` still makes them). With no `profile=` the armature makes its own: a **square whose four corners are spline points** (nearly round, the radius of `radii`, 1 by default); with `profile=` any 2D shape, which is swept from the first node wherever it is. The thickness at a node is the size of the profile times the node's size (the gold ring of its gizmo). `radii` is one number, or -- for nodes that are tuples -- one for each node; given with a profile of your own it is refused (a profile has its own size). Every armature has the box it fills (`_bounds`), so a character exports.
- **`cut_face(armature)` shows the cross-section at the first node.** A linked clone of the profile (`instance`), turned the way the armature leaves the node, with a dot for each point of the profile: pull a dot, double click it, or press the outline, and the profile -- and with it the armature -- changes. An armature made from the menu (*New armature*) is written with a profile of its own above it (`armature_1_cut`, four spline points in the plane z = 0), `armature(..., profile=armature_1_cut)`, and `armature_1_face = cut_face(armature_1)` under it. **Dropping a profile on an armature in the model tree** (or on a profile it uses) swaps the cross-section: the dropped one takes the place of the old one in the call (`ScenePanel::planDropOn`; the same for the profile of an extrusion).
- **The ring of a selected node is a circle of the armature's real radius.** The gold ring of a node used to have the same size on the screen for every point. For a node of an armature it is drawn, and pressed, at the radius the armature has there (the profile's radius times the node's size, as a circle round the node facing the camera), the way Dust3D shows it: size a node against the picture you model over by dragging the ring out or in. With several nodes selected each keeps a faint circle of its own (`Shape::armatureFactor`, `View::ringPx`; `armature()` tells its points the number, `_armature_factor`).
- **`feature_model(features, view, mirror, snap, openings, trim, fill_holes, back, thickness, name)`: feature models, for faces and other delicate parts.** The method of Dust3D, made for FielDev's own design (the source of Dust3D was read for its rules, nothing of it is copied as a limit). Paths of points -- `feature(points, closed, mirror, opening)`, `feature_ring(...)`, a polyline, a spline, a profile, a plain list -- are triangulated in the plane of a view (a Delaunay triangulation that every loop edge is forced into, by flipping the edges that cross it): **every point is a vertex of the surface, none is added or moved, and every loop stays an edge loop** wherever the points are dragged. The surface is a mesh, the feature model the exact distance to it (a shell of `thickness` when it is open, a solid when `back=True` closes it with rings that shrink to a point behind it). What Dust3D fixes is an argument here, and each loop can override it: the **mirror** is off unless asked for and may be any plane (`"x"`, `("x", 2)`, `(point, normal)`; open loops are half shapes -- both ends on the plane makes a ring, one end a path, neither a mirror image; `snap` is how near the plane an end must be), the **view** the points are joined in is any of front, back, left, right, top, bottom or a (direction, up), the points keeping their own depth, **openings** (an eye: a closed loop with nothing in it, inside another closed loop) can be switched off for all or decided per loop, `trim` and `fill_holes` are choices, and loops that cross are refused with a message naming them. **New feature model** in the Character section writes half a face (outline, eye, mouth, nose) with every choice written out. `skeleton_of` leaves a feature model out (it is skin); `character` joins it with the rest. This replaces the first version, which lofted tetrahedra between rings of the same number of points. A dragged point changes the surface when the script runs again, not during the drag (the surface is a mesh).
- **`uvs="armature"` / `uv_armature(margin, size)`: UV maps made from the armature.** Every triangle belongs to the armature or feature model whose surface it is nearest to (the fields of the parts are asked at the vertices); an armature is laid out as a tube along its path (u round it, v along it, the seam straight along the back, the rounded ends carried on), a feature model flat as it was drawn (in the picture of its view, the triangles that face away from the viewer an island of their own, seen from behind), a character made `symmetric="x"` has an island for each half (the second mirrored back; a feature model that holds both halves itself is one island). Islands are in millimetres and are not turned when packed (`uvparts.py`; `character()` keeps its parts and its symmetry axis).
- **Checked here, and not:** the library parts were run with the Python library only (the stitching of a synthetic face: no triangle faces the wrong way or overlaps another, every loop edge is there, the eye is an opening, the mirror, the snap, the views, the closed back, crossing loops refused; the field signs of armatures and features; the template of *New feature model* rendered and run; the cross-section at three different armature directions; the UV islands of a synthetic tube and feature mesh); the C++ (radius circles, the drop of a profile, the menu entry) was not compiled, and nothing was seen in a window.

### Copies and the gizmo of an outline (the same code as FielDes' last two pushes)
- **Ctrl+D duplicates every model, and the linked copy of a small shape is drawn.** A linked copy (`instance(model)`) of a circle or any other small shape was not drawn: the copy is made again from the original's shape scaled by the numbers of the original's gizmo, and that lost the box the shape was said to fill -- the app sizes the render of a shape from its box, and a shape that does not know it is meshed at the scene's plain resolution, where a circle of radius 0.25 is a few cells wide (`instances.py` works the box out from the original's, `_placed_box`). A profile, a polyline or a spline was refused (one notice line under the tree), and so were a point, a field, a material: **Ctrl+D clones every model, the same way -- `copy = instance(model)`**: a profile or a line as the same outline through the images of the original's points, placed by a gizmo of its own (`gizmo()` places whatever is made of points -- it makes itself again through the placed points, `_remake`, the way the symmetries do -- so a point dragged, a number typed or a point added in the original changes every clone; before, the clone was a copy of the profile's statements that followed nothing). The clone has its points -- a dot for each, the image of the original's point (`points.image_dot`, the mechanism the images of a symmetry use) -- pressed, dragged and double clicked it is the original's point that changes, and a press on the clone's outline puts a point on the original, taken back through the clone's place (`Shape::editLine`, `editMap`). The same press on the outline of an IMAGE in a symmetry -- which did nothing before, the images were not editable -- puts the point on the original too, and the point pulled out is drawn at once, while it is dragged, on the original and on every clone and image of it (`View::setPullVirtual`: each takes it to its own place, and counts its points the way it has them -- a mirror image runs the other way round). A point, a field or a surface is cloned as the shape it is, a material as its own value (`instance` hands the value back), an import by its parts, and an expression that has no name is named first. A clone whose original had no gizmo yet is given one from zero: a clone with none is the same tree as its original, and the viewport draws one shape for one tree. **Shift+D**, the plain copy, copies a profile or a line **with the points it is made of** (it kept the same points) (`ScenePanel::duplicateModels`, `linkModels`, `plainCopyEdits`, `modelsToDuplicate`). **A point of a clone or of an image is selected like the original's:** a press on its dot selects the point it is the copy of -- the original's row -- and shows that point's whole gizmo (the arrows, the ring that turns it, the ring that sizes a spline point's influence) at the copy that was pressed, taken through the copy's map (`View::applyActiveCopy`, `Shape::activeCopy`); what is dragged on it, or Delete, is done to the original's point, so every copy follows. **A profile, a polyline or a spline drawn while a symmetry is on** is written with its images as `symmetry_image(stroke, symmetry, k)` of the whole stroke when they touch nothing (`symmetries._outline_image`, `symmetry_creation.simple_images`, `menu_catalog._stroke_text`), so a point dragged, pulled out of its edge or deleted in the stroke is done to its images, as the clone's; strokes whose images meet them keep the shared points.
- **Dragging the gizmo of a point, or of a profile, starts at once.** Every number that a drag changed measured and meshed again every point it moved -- 27 to 40 ms each on the main thread in the first step in FielDes -- for a mesh that nothing draws, because a point is shown as the dot of its gizmo. A point that is not painted keeps its numbers now and renders nothing (`Shape::updateVars`).
- **A profile, a polyline or a spline has a gizmo when it is selected as a whole.** It had none -- its points have the gizmos, and a profile could only be moved point by point. Selecting the outline itself now brings its points into the one shared gizmo, selected or not: its **arrows** and its dot move the outline in all three directions, its three **scale knobs** stretch it along an axis, its three **rings** turn it about the axes, and with Shift the plane squares and the one gold ring scale it evenly, all about the middle of its points -- the shape stays the shape, bigger, stretched or turned, and the points' own scale and rotation (the radius of a round corner, the direction a spline leaves a point) are left as they are. Selected as points alone, the rings change each point's own numbers as before. What is written is the points' own `gizmo(...)` numbers, so the outline and its dots never part (`View::groupGizmo`, `View::outlineSelected`). Selecting the outline also gives each of its points that has no `gizmo(...)` line one, as selecting any model does (`prepareSelection`). **The outline's gizmo starts off, and has a mode of its own in the model tree**: a new profile, polyline or spline shows no gizmo until the gizmo button on its row (or `E`) says *click* or *always*; the choice is written as `x = gizmo(x, mode='click')`, a gizmo line without numbers (`gizmo()` returns the outline itself, with its points, face and handles, and the mode as `_outline_mode`, read in `interpreter.cpp` into `Shape::outlineMode`; `View::outlinesWithGizmo`). An outline that is *always* shown has its gizmo while nothing else is selected.
- **Not built or run yet:** this was merged from FielDes' patches into FielDev's trimmed sources in a cloud session with no window; the engineering parts of the patches (analyses, lattices) are left out.

### UV maps and textures baked from fields
- **UV maps** for `export_mesh(..., uvs=...)`: `uv_box`, `uv_planar`, `uv_cylinder`, `uv_sphere` and **`uv_unwrap`** -- the surface cut into islands where it turns (the cut follows the angle you give, on a smoothed normal), each laid flat
  by a conformal map (planar projection where that is not possible), scaled to one texel size, rotated to its smallest box and packed into the square; a second set (`TEXCOORD_1`) for a lightmap; the picture of the layout (`uv_layout=`).
  `examples/38_uv_maps.py`.
- **`bake(...)`** (`textures=`): every texel of a picture is a place on the surface, and what it is made of is read from the fields there -- the **colour** (materials by region, colours and values that are fields), the **normal map**
  (the exact normal of the field in the tangent space of the mesh: a coarse mesh shaded with it looks like the fine surface), **occlusion, roughness and metalness** (a soft ambient occlusion by tracing the field), with padding
  at the islands' edges. PNG files are written by the library itself (`fieldev.stdlib.pngfile`); a `.glb` carries the pictures inside it, an OBJ names them in its `.mtl`. `examples/39_baked_textures.py`.
- **Exact vertex normals** from the gradient of the field (`normals=`), tangents in the glTF, normals in the OBJ and the PLY.

### PBR materials
- `material(...)`: colour, roughness, metalness, opacity and emission, each a number **or a field**; alpha mode, double sidedness, IOR, transmission, clear coat, sheen, normal scale; `where=` for the region of a material;
  **24 presets** (`material_preset`, `material_presets`). Written as glTF materials with their extensions, and as OBJ + MTL.
- **`with_materials(model, [...])`**: the model shown in the viewport in the colours of its materials (the same layers an export paints, found at every vertex of the mesh; the edge between two is cut as sharp as the mesh is fine), with a
  key of their names; `export_mesh` writes the same materials when it is not given `materials=`. The roughness, metalness, glow, opacity and textures are only in the exported file.

### Rigging
- `joint`, `mirror_joints`, `skeleton_of`; skin weights by the nearest bone with a blend at the joints, **a joint that owns a place** (`influence=` a body or a field: the skin there follows it alone, fading outside it over
  `skin_falloff`), and up to **eight** joints a vertex (`max_influences`, `JOINTS_1` / `WEIGHTS_1`). A rigged glTF has the skin, the inverse bind matrices and the weights. The skeleton is the output of a model that is not animated:
  FielDev writes the bind pose; it has no animation and no morph targets.

### Exporting for a game engine
- `export_mesh`: the unit and the up axis (`units=`, `up=`), a budget of triangles (`max_triangles=`) and `export_lods`, a mesh that is exactly symmetric (`symmetric=`), the origin where the asset stands (`pivot="base"`), materials
  by region and vertex colours from fields; STL, OBJ, PLY, 3MF, glTF (`.glb`, `.gltf`), FBX, OFF and DXF.

### The product
- **Renamed from FielDes**, so that FielDev shares nothing with an installed FielDes: the application and organisation names, the `FIELDEV_*` environment variables, the Python package `fieldev`, the kernel libraries
  (`fieldev`, `fieldev-stdlib`), the `.fieldevapp` file type and the user-visible name. The licences stay: GPL 2 or later for the application, MPL 2.0 for libfive (`NOTICE.md`).
- **Taken out** (they are not what a game asset needs): the finite-element, thermal and flow solvers, topology optimisation, lattices, STEP / CAD import, manufacturing checks, and their menus, cards, glyphs and examples. The
  examples are rebuilt on primitives, fields and points.
